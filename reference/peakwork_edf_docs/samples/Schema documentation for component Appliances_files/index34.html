              <xs:documentation xml:lang="de">Das Type-Attribut legt zusammen mit dem Code-Attribut fest, wie das Appliance-Element angewandt wird.

Sofern keine Appliance auf Base, ExtraDay oder Board definiert wird, wird das Extra auf die Basispreiskomponenten angewandt (Base, ExtraDay und Board).
Die Extra-Appliances sind komplett losgeslöst von den Basispreiskomponenten-Appliances.

Die möglichen Werte des Code-Attributes hängen vom Wert des Type-Attributes ab.

Das Attribut kann folgende Werte haben:
Extra: Type="Extra" legt fest, dass das Extra-Element auf ein anderes Extra-Element angewandt wird. Wenn das Code-Attribut des aktuellen Appliance-Elementes identisch ist mit dem ApplianceCode-Attribut eines anderen Extra-Elementes, dann wird das aktuelle Extra auf das andere Extra angewandt. Beispiel: Ein Frühbucherrabatt wird auf einen Zuschlag angewandt. Wenn kein Attribut Code verwendet wird, dann wird das aktuelle Extra auf alle anderen aktiven Extras angewandt. Diese Anwendung mit Type="Extra" ist als Erweiterung zu verstehen, d.h. es findet die Anwendung auf das in der Appliance angegebene Extra statt jedoch auch die auf die Basispreiskomponenten.

Charge: Bei Type="Charge" dürfen nur festgelegte Codes verwendet werden. Die möglichen und festgelegten Werte sind dem Code-Attribut zu entnehmen. Diese Appliance ist eine Einschränkung der Anwendung des Extras auf bestimmte Basispreiskomponenten. Sofern keine Appliance mit Type="Charge" definiert wird, wird das Extra auf alle Basispreiskomponenten angewendet.

Person: Type="Person" wird gesetzt, um in einem Extra auf eine bestimmte Personengruppe zu referenzieren. Beispiel: Die Ermäßigung gilt nur für Kinder. Im Code-Attribut muss der Personentyp gesetzt werden. Die möglichen und festgelegten Werte sind dem Code-Attribut zu entnehmen. Wenn der Wert "Person" gesetzt wird, können die Attribute MinAge und MaxAge zusätzlich genutzt werden. Wenn keine Appliance mit Type="Person" verwendet wird, dann wird das Extra auf alle Personen angewendet.

Fixed: Bei Type="Fixed" werden Base und ExtraDay überschrieben.

Stay: Mindestens oder höchstens diese Anzahl der Tage müssen innerhalb des Zeitraumes der oben genannten DateRestriction liegen.

Date: Hierüber kann gesteuert werden, dass eine Charge oder Reduction auf die gesamte Reisedauer angewandt wird und nicht nur auf die Tage, die in die DateRestriction fallen.

GuestCharge: Type="GuestCharge" legt fest, dass das Extra auf ein GuestCharge-Element angewandt wird. Der Wert des Code-Attributes muss dann identisch sein mit dem Wert des ApplianceCode-Attributes des GuestCharge-Elementes.</xs:documentation>
              <xs:documentation xml:lang="en">The Type attribute specifies together with the Code attribute how the Appliance element is applied.

As far as no Appliance element is defined for Base, ExtraDay or Board, the Extra will be applied on all basic price components (Base, ExtraDay and Board).
Appliances on Extras are independent from Appliances on basic price components.

The possible values of the Code attribute depend on the value of the Type attribute.

Extra: Type="Extra" specifies that the Extra element is applied to another Extra element. If the Code attribute of the current Extra element is identical with the ApplianceCode attribute of another Extra element, the current extra is applied to the other extra. The appliance to extra is always just an additional appliance. If no Appliance with Type="Charge" is used additionally to the Appliance with Type="Extra", the current extra will apply to the specified extra and also to the basic price components.

Charge: If the Type contains the Charge value, only pre-defined codes may be used. The possible and pre-defined values are taken from the Code attribute. This appliance is a constraint, because without any Appliance element with Type="Charge" the extra applies on each basic price component. If appliances on Type="Charge" are defined, the extra applies just on the specified basic price components.

Person: Type="Person" is set to reference a specific group of persons in an extra. For example, the reduction applies only to children. The person type must be set in the Code attribute. The possible and pre-defined values are taken from the Code attribute. When the Person value is set, the MinAge and MaxAge attributes can also be used. If no Appliance with Type="Person" is used, the Extra applies to all persons.

Fixed: If Type contains the Fixed value, Base and ExtraDay will be overwritten.

Stay: This number of days must at least or at most lie in between the time range defined in the DateRestriction element of the Extra.

GuestCharge: If Type is set to GuestCharge, the code references to the attribute ApplianceCode in GuestCharges. The Extra is then only applied on the referenced GuestCharge element.</xs:documentation>

            <xs:annotation>
              <xs:documentation xml:lang="de">Das Code-Attribut legt zusammen mit dem Type-Attribut fest, wie das Appliance-Element angewandt wird.
Die möglichen Werte des Code-Attributes hängen vom Wert des Type-Attributes ab.

Dabei können die verschiedenen Preisbezüge in Kombination miteinander verwendet werden. Ausnahme: Die Attributwerte "ExtraDay" und "AllExtraDays" sind nicht miteinander kombinierbar.

Wenn Type gleich Charge gesetzt ist, sind die folgenden Codes möglich:

Type="Charge"
* BasePrice: Der Zu- oder Abschlag bezieht sich auf den Grundpreis.
* Board: Der Zu- oder Abschlag bezieht sich auf die Verpflegungszuschläge.
* ExtraDay: Der Zu- oder Abschlag bezieht sich auf die Verlängerungstage innerhalb einer Preisfindung, die über die Basisdauer hinausgehen.
* AllExtraDays: Der Zu- oder Abschlag bezieht sich auf den gedachten Nur-Hotel-Anteil und damit auf den Verlängerungstag. Für die gesamte Reisedauer wird der Verlängerungspreis als Grundlage für die Berechnung der Reduktion genutzt.
* None: Der Zu- oder Abschlag wird nicht auf die Basispreiskomponenten (BasePrice, ExtraDay, Board) angewendet, sondern auf den Gesamtpreis.
* BaseCharge: Der Zu- oder Abschlag wird zuerst auf die BaseCharges angewandt, danach werden GuestCharges berechnet. Dies bedeutet, dass eine bestehende Kinderermäßigung oder Erwachsenen Ermäßigung auch auf ein Extra abgewendet wird. Beispiel: Es besteht eine Kinderermäßigung von 50% und ein Zuschlag in Form eines Extras in Höhe von 30 EUR. Mit dem Attribut Appliance Type="Charge" Code="BaseCharge" kostet der Zuschlag für das Kind bei einer Kinderermäßigung von 50% =15 EUR. Wenn die Attribute Type="Charge" und Code="BaseCharge" nicht gesetzt ist, bedeutet dies, dass eine Kinderermäßigung oder eine Erwachsenenermäßigung nicht auf den Zuschlag angewendet wird.

Defaultwerte und zu beachtende Regeln:
Für die Parameter Type="Charge" bestehen die folgenden Defaultwerte:
Das Extra bezieht sich immer auf die 3 Preiskomponenten "BasePrice", "ExtraDay" und "Board", wenn das Attribut Type="Charge" nicht gesetzt ist.
Sofern eine der drei Preiskomponenten genutzt wird, dann muss eine explizite Auflistung erfolgen, für welche Preiskomponenten das Extra gilt.
Weiterhin gilt in Bezug auf den Wert Type="Charge" und Code="BaseCharge" der Default, dass eine Kinderermäßigung oder Erwachsenenermäßigung nicht angewendet wird, sofern diese Parameter nicht geschrieben werden.

Beispiel:
7 Tage Grundpreis: 400,00 EUR
1 Verlängerungstag: 50,00 EUR
10 Tages-Reise: 550,00 EUR
Ermäßigung: 10 Prozent
ExtraDay: 3 x 50,00 EUR x 10 Prozent = 15,00 EUR
AllExtraDays: 10 x 50,00 EUR x 10 Prozent = 50,00 EUR


Type="Extra"
Bei Type="Extra" verweist das Code-Attribut auf ein Extra mit dem gleichen Code.

Beispiel:
Es besteht ein Frühbucherrabatt von 5,00 EUR pro Tag.
Der Frühbucherrabatt ist anwendbar auf einen Special Offer 7=6.
Der Special Offer hat den Code "ID" für Dauernincentive.

Der Frühbucher erhält in diesem Beispiel das Element Appliance mit dem Type="Extra" und Code="ID".
Dies bedeutet, er bezieht sich auf Extras mit dem Code ID und damit auf Dauernincentives.
Wenn sich der Frühbucherrabatt auf den Dauernincentive bezieht, gilt die Berechnung implizit auf die bezahlte Dauer: In diesem Falle wird der Frühbucherrabatt 6 mal - für 6 Tage - berechnet.
Wenn das Element Appliance nicht gesetzt ist, der Frühbucherrabatt aber mit dem Dauernincentive kompatibel ist, wird der Frühbucherrabatt insgesamt 7 Mal - für 7 Tage berechnet.


Type="Person"
Bei Type="Person" kann das Code-Attribut die folgenden Werte haben:
* A: Adult
* C: Child
* I: Infant
* B: Vollzahler
* N: Nonbillable guest (alle Personen, die nicht Vollzahler sind)


Type="Fixed"
Bei Type="Fixed" kann das Code-Attribut die folgenden Werte haben:
* BasePrice: Der Festpreis ersetzt nur den Basispreis der BaseCharges.
* Board: Der Festpreis ersetzt nur den Verpflegungszuschlag der BoardCharges.
* ExtraDay: Der Festpreis ersetzt nur den Verlängerungspreis der BaseCharges.
* AllExtraDays: Der Festpreis ersetzt den gedachten Nur-Hotel-Anteil und damit jeden Tag der Reise.

Beispiel:
7 Tage Grundpreis: 400,00 EUR
1 Verlängerungstag: 10,00 EUR
10-Tages-Reise: 430,00 EUR
Ermäßigung: 5 EUR Festpreis
ExtraDay: 3 x 5,00 EUR = 15,00 EUR
AllExtraDays: 10 x 5,00 EUR = 50,00 EUR


Type="Stay"
Type="Stay" kann nur im Zusammenhang mit MinCount/MaxCount in Verbindung mit Dauernincentives genutzt werden.
Bei Type="Stay" ist nur Code="DiscountedNights" möglich:
* DiscountedNights: MinCount und MaxCount beinhalten hier die minimale bzw. maximale Gesamtanzahl an Tagen pro Buchung, die reduziert werden dürfen, damit ein Extra gilt. Vor jeder Anwendung des Extras muss geprüft werden, ob die maximale Anzahl an reduzierten Nächten für diese Buchung verbraucht ist.

Beispiel:
14=12 und 7=6, Appliance Type="Stay", Code="DiscountedNights", MinCount="1", MaxCount="2", Reisedauer 21 Tage
Der Incentive 7=6 wird nicht mehr angewendet, weil die maximale Anzahl der reduzierbaren Nächte (MaxCount="2") bereits durch das Incentive 14=12 erreicht ist.


Type="Date"
Bei Type="Date" kann das Code-Attribut folgenden Wert haben:
* AllNights: Hierüber kann gesteuert werden, wenn die Reisedauer nicht in die komplette Date-Range hineinpasst, dass trotzdem alle Tage berechnet werden.

Beispiel:
Reisedauer 7 Tage
DateRestriction endet 2 Tage vor Reiseende. Also sind die 7 Tage nicht komplett innerhalb der DateRestriction.
Eine Ermäßigung würde normalerweise auf 5 Tage angewendet werden.
Mit Type="Date" Code="AllNights" wird die Ermäßigung auf 7 Tage angewendet.


Type="GuestCharge"
Bei Type="GuestCharge" legt das Code-Attribut fest, auf welches GuestCharge-Element das Extra-Element angewandt wird. Der Wert des Code-Attributes muss dann identisch sein mit dem Wert des ApplianceCode-Attributes des GuestCharge-Elementes.</xs:documentation>
              <xs:documentation xml:lang="en">The Code attribute specifies together with the Type attribute how the Appliance element is applied.
The possible values of the Code attribute depend on the value of the Type attribute.

The various price references can be used in combination with each other. Exception: The attribute values ExtraDay and AllExtraDays cannot be combined with each other.

If Type equals Charge, the following codes are allowed:

* BasePrice: The extra charge or reduction relates to the base price.
* Board: The extra charge or reduction relates to the board charges.
* ExtraDay: The extra charge or reduction relates to the extra days within a pricing that exceed the base duration.
* AllExtraDays: The extra charge or reduction relates to the intended Hotel Only portion and thus to the extension day. The extension price is used as the basis for calculating the reduction for the entire travel duration.
* None: prevents the extra from being applied on any base price component (BasePrice, ExtraDay, Board). By that, the extra charge or deduction is only applied to the total price.
* BaseCharge: The extra charge or reduction is first applied to the BaseCharges before GuestCharges are calculated. This means that an existing child or adult discount is also applied to an extra. Example: There is a child discount of 50% and an additional charge in the form of an extra costing of EUR 30. With the Appliance Type="Charge" and Code="BaseCharge" attributes set, the extra charge for
the child with a child discount of 50% equals EUR15. If the Type="Charge" and Code="BaseCharge" attributes are not set, this means, that a child discount or adult discount is not applied to the additional charge.

Default values and rules to be observed:
The following defaults exist for the Type="Charge" parameter:
The extra always relates to the 3 price components "BasePrice", "ExtraDay" and "Board" when the Type="Charge" attribute is not set. If one of these three price components is used, the price components for which the extra applies must be explicitly listed.
Generally, with regard to the Type="Charge and Code="BaseCharge" value, the default is that a child or adult discount is not applied if these parameters are not written.

Example:
7 days base price: 400.00 EUR
1 extra day: 50.00 EUR
10-day journey: 550.00 EUR
Reduction: 10 percent
ExtraDay: 3 x 50.00 EUR x 10 percent = 15.00 EUR
AllExtraDays: 10 x 50.00 EUR x 10 percent = 50.00 EUR


Type="Extra"
If Type equals Extra, the code can be freely defined.
The code references an extra, that is already set with the same code.

Explanation
An early bird with a discount of 5.00 EUR per day already exists. The early bird discount can be applied to a special offer 7=6.
The special offer is assigned the code "ID" for duration incentive. In this example, the early bird is assigned the Appliance element with Type = Extra and Code = ID. This means, it refers to extras with the code ID and therefore to duration incentives.
If the early bird refers to the duration incentive, the calculation applies implicitly to the paid duration: In this case, the early bird is calculated 6 times - for 6 days.
If the Appliance element is not set, but the early bird is compatible with the duration incentive, the early bird is calculated a total of 7 times - for 7 days.

Type="Person"
If Type equals Person, the Code attribute can have the following values:
* A: Adult
* C: Child
* I: Infant
* B: Full payer
* N: Non-Billable Guest (all non-charged persons)

Type="Fixed"
If Type equals Fixed, the Code attribute can have the following values:
* BasePrice: The fixed price only replaces the base charge of the BaseCharges
* Board: The fixed price only replaces the BoardCharges
* ExtraDay: The fixed price only replaces the extra day price of the BaseCharges
* AllExtraDays: The fixed price replaces the intended Hotel Only portion and thus every day of the stay.

Example:
7 days base price: 400.00 EUR
1 extra day: 10.00 EUR
10-day journey: 430.00 EUR
Reduction: 5 EUR fixed price
ExtraDay: 3 x 5.00 EUR = 15.00 EUR
AllExtraDays: 10 x 5.00 EUR = 50.00 EUR


Type="Stay"

The Stay type can only be used in conjunction with MinCount/MaxCount in association with duration incentives.
If Type equals Stay, the code "DiscountedNights" is possible:
* DiscountedNights: DiscountedNights contains a minimum and a maximum total number of days per booking that may be reduced, so that an extra applies. Before any application of this extra, it must be verified whether the maximum number of reduced nights is used up for this reservation.

Example: 14=12 and 7=6, Appliance Type="Stay", Code="DiscountedNights", MinCount="1", MaxCount="2", duration of stay 21 days
The incentive 7=6 is no longer applied because the maximum number of reducible nights (MaxCount="2") has already been reached through the incentive 14=12.</xs:documentation>
