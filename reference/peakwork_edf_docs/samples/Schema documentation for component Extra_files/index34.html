Element Extra
Namespace http://www.vilauma.de/edf/Hotel
Annotations
 
Das Extra-Element definiert eine Ermäßigung oder einen Zuschlag. Mit einem Extra-Element können z.B. Frühbucherrabatte und zusätzliche Leistungen abgebildet werden. Das Extra-Element kann beliebig oft innerhalb eines Produktes verwendet werden.
 
The Extra element defines a reduction or an extra charge. An Extra element can represent for example early bird discounts and additional services. The Extra element can be used as often as desired within a product.

ApplianceCode xs:string optional 
Das ApplianceCode-Attribut legt den Code des Extra-Elementes fest. Dieser Code ist veranstalterspezifisch und frei definierbar.

Mit dem ApplianceCode-Attribut des Extra-Elementes und dem Code-Attribut des Appliance-Elementes kann man festlegen, dass das eine Extra-Element auf ein anderes angewandt werden soll.

Beispiel:
<Appliance Code="SOID" Type="Extra"/>
Das Extra mit diesem Appliance-Element wird auf alle Extras angewandt, die ApplianceCode="SOID" haben.

Der Player kann pro Hotel-EDF-Datei maximal 31 ApplianceCodes verarbeiten. Hotels, die mehr als 31 Appliance Codes haben, werden vom Player verworfen. Appliance Codes aus Global Extras werden dazu gerechnet, sofern diese auf das Hotel angewendet werden.
 
The ApplianceCode attribute specifies the code of the Extra element. This code is tour operator specific and is user-definable.

By using the ApplianceCode attribute of the Extra element and the Code attribute of the Appliance element, one can specify that one of the Extra elements is applied to the other one.

Example:
<Appliance Code="SOID" Type="Extra"/>
The extra that has this Appliance element is applied to all extras that have ApplianceCode="SOID".

The Player can process up to 31 appliance codes per hotel EDF file. Hotels with more than 31 appliance codes will be discarded by the Player. Appliance codes from global extras are also included in the calculation if they are applied to the hotel.

CombiGroupId xs:int optional 
Das CombiGroupId-Attribut legt die Gruppe fest, zu der das Extra-Element gehört.
Diese Gruppe ist eine Gruppe von Extras, die miteinander kombiniert werden können.

Beispiel: Ein Frühbucherrabatt wird mit einer Kinderermäßigung kombiniert.
Mehr zur Kombinierbarkeit:
* siehe Appliance-Element (Extra/Reductions/Reduction/Appliances/Appliance oder Extra/Charges/Charge/Appliances/Appliance)
* siehe CompatibleWith-Element (Extra/CompatibleExtras/CompatibleWith)

Der Wert von CombiGroupId muss eine Ganzzahl sein.
Der Standardwert ist 0.

Pro Hotel kann es maximal 127 verschiedene Gruppen geben.
Hinweis: Bei Saisonübergängen ("season merge") werden mehrere EDF-Dateien zu einem Hotel (also zu einer OXB-Datei) zusammengefügt. Allerdings bleibt die Obergrenze von 127 verschiedenen Gruppen-IDs bestehen.
 
The CombiGroupID attribute is used to specify which group an extra belongs to.
These groups can be used to combine extras.

Example: An early bird discount is to be combined with a child discount.
More about combinability:
* see the Appliance element (Extra/Reductions/Reduction/Appliances/Appliance oder Extra/Charges/Charge/Appliances/Appliance)
* see the CompatibleWith element (Extra/CompatibleExtras/CompatibleWith)

The value of CombiGroupId must be an integer.
The standard value is 0.

There can be a maximum number of 127 different groups per hotel.
Note: In case of a season merge, multiple EDF files are merged for one hotel (i.e. into a single OXB file). However, the maximum number of 127 different group IDs still applies.
FlightReferenceCode xs:string optional 
Das FlightReferenceCode-Attribut verweist auf ein Extra, das im Flug gesetzt ist.

Anwendungsfall:
Es bestehen Flugzuschläge mit einem bestimmten Kenner. Diese Flugzuschläge sind nur gültig, wenn eine Ermäßigung im Hotel den gleichen Kenner aufweist.
So will ein Veranstalter beispielsweise Lastminute-Buchungen zu einem günstigeren Preis anbieten.
Normalerweise besteht ein Flugzuschlag von 90,00 EUR. Für alle Lastminute-Angebote entfällt jedoch der Zuschlag.

Beispiel 1:
Flug:
<Extras>
    <Extra HotelReferenceCode="Y">
    </Extra>
</Extras>

Hotel:
<Extras>
    <Extra FlightReferenceCode="Y">
    </Extra>
</Extras>

In diesem Beispiel wird das Flug-Extra nur angewendet, wenn bei der Bündelung einer Pauschalreise das erste Hotel (Grundpreishotel) ein Extra enthält, das im FlightReferenceCode-Attribut den Wert "Y" hat.

Anwendungsfall:
Es besteht ein Flugabschlag mit dem Kenner "Y". Der Flugabschlag wird nur gewährt, wenn der Flug mit einem Hotel-Extra kombiniert wird, welches den gleichen Kenner "Y" aufweist.

Beispiel 2:
Flug:
<Extras>
    <Extra>
    </Extra>
</Extras>

Es ist kein HotelReferenceCode-Attribut gesetzt.
Das Flug-Extra gilt für alle Hotels und Extras.

Beispiel 3:
Flug:
<Extras>
    <Extra HotelReferenceCode="NA">
    </Extra>
</Extras>

Das Flug-Extra gilt für alle Hotels und Extras, in denen KEIN Reference-Code gesetzt ist.
 
The FlightReferenceCode attribute refers to an extra that is defined in the flight.

Application:
There are additional flight charges with a specific identifier. These additional flight charges are only valid, if a reduction in the hotel has the same identifier.
In this way, a tour operator wants to offer last-minute bookings at a better price.
Normally, there is an additional flight charge of 90.00 EUR. However, the additional charge is waived for all last-minute offers.

Example 1:
Flight:
<Extras>
    <Extra HotelReferenceCode="Y">
    </Extra>
</Extras>

Hotel:
<Extras>
    <Extra FlightReferenceCode="Y">
    </Extra>
</Extras>

In this example, the flight extra is only applied, if in the bundling of a package tour the first hotel (basic price hotel) contains an extra that has FlightReferenceCode="Y".

Application:
There is a reduced flight charge with the identifier "Y". The reduced flight charge is only granted, if the flight is combined with a hotel extra that has the same identifier "Y".

Example 2:
Flight:
<Extras>
    <Extra>
    </Extra>
</Extras>

No HotelReferenceCode attribute is set.
The flight extra applies to all hotels and all extras.

Example 3:
Flight:
<Extras>
    <Extra HotelReferenceCode="NA">
    </Extra>
</Extras>

The flight extra applies to all hotels or extras in which NO reference code is set.

Mandatory MandatoryEnum True optional 
Das Mandatory-Attribut legt fest, ob der Preis dieses Extras in den Zimmerpreis mit eingerechnet wird und ob der Preis dieses Extras in der Antwort des Players einzeln zurückgegeben wird.

Mögliche Werte:
* True: Der Preis des Extras wird in den Zimmerpreis mit eingerechnet.
* False, Disable: Das Extra wird verworfen und nicht in den Zimmerpreis mit eingerechnet.
* Include: Das Extra wird in den Zimmerpreis mit eingerechnet, und dieser Extra-Preis wird in der Player-Antwort zusätzlich noch einzeln mit zurückgegeben.
* Exclude: Das Extra wird nicht in den Zimmerpreis mit eingerechnet, und dieser Extra-Preis wird in der Player-Antwort zusätzlich noch einzeln mit zurückgegeben.
 
The Mandatory attribute specifies whether the price of this extra is added to the room price and whether the price of this extra is separately returned in the Player response.

Possible values:
* True: The extra is added to the room price.
* False, Disable: The extra is rejected and isn't added to the room price.
* Include: The extra is added to the room price and the price of this extra is separately returned in the Player response.
* Exclude: The extra is not added to the room price and the price of this extra is separately returned in the Player response.
OffersAllowed xs:boolean true optional 
Das OffersAllowed-Attribut beeinflusst, mit welchen BaseCharges-Elementen das Extra kombiniert werden kann.

Mögliche Werte:
* true: Wenn Extra/@OffersAllowed="true", dann wird das Extra im BaseCharge-Element angewandt, wenn BaseCharges/@OffersAllowed="true" gesezt ist.
* false: Wenn Extra/@OffersAllowed="false", dann wird das Extra immer im BaseCharge-Element angewandt, unabhängig davon, ob BaseCharges/@OffersAllowed="true" or  BaseCharges/@OffersAllowed="true" gesetzt ist.

Siehe auch /HotelRoot/SellingData/Rooms/Room/ChargeBlocks/ChargeBlock/Sections/Section/BaseCharges/@OffersAllowed
 
The OffersAllowed attribute influences with which BaseCharges elements the extra can be combined.

Possible values:
* true: If Extra/@OffersAllowed="true" then the Extra is only applied to the BaseCharge if BaseCharges/@OffersAllowed="true".
* false: If Extra/@OffersAllowed="false" then the Extra is always applied to the BaseCharge regardless whether the BaseCharges/@OffersAllowed="true" or  BaseCharges/@OffersAllowed="true".

See also /HotelRoot/SellingData/Rooms/Room/ChargeBlocks/ChargeBlock/Sections/Section/BaseCharges/@OffersAllowed
SortIndex xs:int optional 
Das SortIndex-Attribut beeinflusst die Sortierreihenfolge, in der die Extras abgearbeitet werden.

Je kleiner der Wert von SortIndex, desto höher ist die Priorität der Abarbeitung.

SortIndex steht im engen Zusammenhang mit dem CompatibleExtras-Element.
 
The SortIndex attribute has an influence on the order in which extras are processed.

The lower the value of SortIndex, the higher the priority of the processing.

SortIndex is closely related to the CompatibleExtras element.
