Restrictions﻿

Last modified: 25 February 2026

The Restrictions element is a container element for one or more Restriction elements. If a Restrictions element has more than one Restriction element, they are combined by a logical AND.

Restrictions are understood as booking restrictions, minimum and maximum stays, fixed arrival days, etc.

The Restrictions element contains restrictions for the level at which it is located. This allows an assignment of restrictions with regard to time frame (date), days of the week (weekday), durations of stay (stay), season labels (season), persons (guests), board (board) and flights (flights), see Restriction types. These restrictions can be set both at the hotel level and at the room level:

Hotel level:

  • HotelRoot/SellingData/Extras/Extra/Restrictions, see also Extras

  • HotelRoot/SellingData/Restrictions

Room level:

  • HotelRoot/SellingData/Rooms/Room/Restrictions

  • HotelRoot/SellingData/Rooms/Room/Extras/Restrictions

  • HotelRoot/SellingData/Rooms/Room/ChargeBlock/Restrictions

  • HotelRoot/SellingData/Rooms/Room/ChargeBlock/Extras/Extra/Restrictions

Consider following:

  • If the restriction is on hotel level or on room level and the conditions of the restriction are met, the room can be booked.

  • If the restriction is on extra level and the conditions of the restrictions are met, the extra is applied.

Restrictions are not supported in the PXBMerge with one exception: HotelRoot/SellingData/Rooms/Room/Restrictions/Restriction/FlightRestrictions/FlightRestriction/@ArrivalAirport meaning, the FlightRestriction element is only supported on the level of the Room element, if the FlightRestriction is related to the ArrivalAirport.

Restriction types﻿

A Restriction element includes following "types", i.e. child elements and their attributes:

Consider: The following "...Restrictions" elements (DateRestrictions, StayRestrictions etc.) are combined with each other by a logical AND.

  • DateRestrictions; including the attributes: Condition, Invert, Operator, ReleaseTime, Request

    • DateRestriction including the attributes: ApplyTo, ApplyToMode, BookingEnd, BookingStart, Start, End, ExtraMaxApply, MaxBookingOffset, MinBookingOffset

  • StayRestrictions; including the attributes: Condition, Invert, Operator

    • StayRestriction; including the attributes: ApplyTo, Max, Min, Mode, Sequence

  • GuestRestrictions; including the attributes: Invert

    • GuestRestriction; including the attributes: MaxPerson, MinPerson, PersonType (note that starting with hotel EDF 5.0.0, the Condition attribute has been removed for GuestRestrictions; if you want to restrict bookings for specific guests, e.g. children, during certain periods (if-then-condition), instead you can:

      • write the Occupancy element (split) for the specific date range (Start and End attributes) and block the person type, e.g. children.

      • write the BaseCharges with GuestRestrictions.

      • write the Occupancy element in the allotment file (HotelAllotmentRoot/SellingData/Allotments/Allotment/Occupancy).

  • WeekdayRestrictions; including the attributes: Condition, Invert, Operator

    • WeekdayRestriction; including the attributes: ApplyTo, Mask (mandatory)

  • BoardRestrictions; including the attributes: Condition, Invert

    • BoardRestriction; including the attribute: Code (mandatory)

  • SeasonRestrictions; including the attributes: Condition, Invert, Operator

    • SeasonRestriction; including the attributes: ApplyTo, ApplyToMode, FlightPriceTable, HotelPriceTable, Label (mandatory)

  • HotelRestrictions; including the attribute: Invert

    • HotelRestriction; including the attributes: IataCode, RoomCode

  • FlightRestrictions; including the attributes: Condition, Invert, Operator

    • FlightRestriction; including the attributes: AirType, Airline, AllotmentBinding, AllotmentFix, ArrivalAirport, DepartureAirport, BookingClass, Code, FlightLabel, FlightPriceTable, TimeMax, TimeMin, Type, Weekday

Principles of restrictions﻿

Relation of different restriction types

"...Restrictions " elements are joined by a logical AND, which means all restrictions apply at the same time, e.g. DateRestrictions and StayRestrictions apply equally.

In order to create an "if/when"-relation between restrictions, you must change the attribute Condition to "false" in the second restriction (Condition=true" is the default). Thereby, the following relationship will be created: "If condition A is met, then restriction B applies." The if-part describes the condition. The then-part describes the restriction (Condition="false").

Example:

with Condition="true" (default), the following XML snippet restricts the booking to a certain period together with a min-stay:

<Restrictions>
  <Restriction>
    <DateRestrictions>
      <DateRestriction ApplyTo="Within" Start="2021-03-05" End="2021-03-10"/>
    </DateRestrictions>
    <StayRestrictions>
      <StayRestriction Min="P3D"/>
    </StayRestrictions>
  </Restriction>
</Restrictions>

with Condition="false", the following XML snippet obliges a min-stay within a certain travel period:

<Restrictions>
  <Restriction>
	<DateRestrictions>
	  <DateRestriction ApplyTo="Within" Start="2021-03-05" End="2021-03-10"/>
	</DateRestrictions>
	<StayRestrictions Condition="false">
	  <StayRestriction Min="P3D"/>
	</StayRestrictions>
  </Restriction>
</Restrictions>

Relation of the same restriction

"...Restriction" elements of the same type are joined by a logical OR, e.g. several WeekdayRestriction elements (Operator="OR" is the default).

To read more about changing the relation of restrictions, see Condition, Invert, Operator attributes in the Restrictions elements in the "Extras" chapter.

Use cases﻿

How to ensure arrivals on Mondays in July are not permitted﻿

...
<SellingData Currency="EUR">
    <SeasonDefinitions Start="2021-01-01" End="2021-12-31"/>
    <Rooms>
      <Room Code="12345678">
        <Descriptions>
          <Description Language="DE">Doppelzimmer (1 oder 2 Betten), Meeresblick</Description>
          <Description Language="EN">Double room (1 or 2 beds), sea view</Description>
          <Description Language="**">Double room (1 or 2 beds), sea view</Description>
        </Descriptions>
        <Occupancies>
            <Occupancy Min="1" Max="4" MinAdult="1" MaxAdult="3" MinChild="0" MaxChild="2" MinChargedPersons="1" Start="2021-01-01" End="2021-05-31">
                <Children MinAge="2" MaxAge="12"/>
            </Occupancy>
        </Occupancies>
        <Boards>
          <Board Code="F" GlobalType="BB"/>
        </Boards>
        <Restrictions>
          <Restriction>
			<DateRestrictions>
				<DateRestriction ApplyTo="Within" Start="2021-07-01" End="2021-07-31"/>
			</DateRestrictions>
            <WeekdayRestrictions Condition="false">
              <WeekdayRestriction ApplyTo="Arrival" Mask="NYYYYYY"/>
            </WeekdayRestrictions>
          </Restriction>
        </Restrictions>
