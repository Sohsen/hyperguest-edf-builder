Restrictions element﻿

Last modified: 25 February 2026

A sales control EDF file may define different sets of filters by adding different Restriction elements which are applied in both the Converter and PXB2Tool. These elements are logically OR linked.

warning

If any of the filters apply, which are defined as restrictions in the SalesControl EDF, the flight will be discarded.

DateRestriction element﻿

A DateRestriction element may have the following attributes:

  • Start: Date. The start date of the date period from which flights are excluded.

    Format: YYYY-MM-DD. Example: 2015-05-20.

  • End: Date. The end date of the date period from which flights are excluded.

    Format: YYYY-MM-DD.

  • MinBookingOffset: Period. The date offset specifying the earliest possible date for booking.

    Format: P\[N\]D (where \[N\] stands for one or more digits). Example: P20D means 20 days.

  • MaxBookingOffset: Period. The date offset specifying the latest possible date for booking.

Since Box version 1.65.0 / Player version 2.39.0, the PXB2Tool supports the DateRestriction element. Check the Limitations within PXB2Tool.

Examples﻿

One restriction﻿

The following DateRestrictions element discards all flights between July, 15th and July, 16th 2019 that can be booked between 10 days and one day before the flight date.

<Restriction>
    <DateRestrictions>
        <DateRestriction Start="2019-07-15"
                         End="2019-07-16"
                         MinBookingOffset="P1D"
                         MaxBookingOffset="P10D"/>
    </DateRestrictions>
</Restriction>

The following DateRestrictions element blocks flights on the 28.10. and 29.10.2019. Moreover, if today is 26.10.2019, it would block a length of stay (LOS) of 2-3 days, and if today is 27.10.2019, it would block a LOS of 1-2 days.

<Restriction>
    <DateRestrictions>
        <DateRestriction Start="2019-10-28" End="2019-10-29"/>
    </DateRestrictions>
</Restriction>

Two restrictions﻿

While the DateRestrictions element in the above example contains only one DateRestriction element, the following one has two DateRestriction elements. That means, all flights are discarded that either have a flight date between July, 15th and July, 16th 2019 or can be booked between 10 days and one day before the flight date.

<Restriction>
    <DateRestrictions>
        <DateRestriction Start="2019-07-15" End="2019-07-16" />
        <DateRestriction MinBookingOffset="P1D" MaxBookingOffset="P10D"/>
    </DateRestrictions>
</Restriction>

Restriction with Invert attribute﻿

The following DateRestrictions element has its Invert attribute set to true. That means, only flights with flight date between July, 17th and July, 19th 2019 will be included, all other flights will be discarded.

<Restriction>
    <DateRestrictions Invert="true">
        <DateRestriction Start="2019-07-17" End="2019-07-19"/>
    </DateRestrictions>
</Restriction>

The following DateRestrictions allows all flights starting from 05.11.2019. However, if today is the 23.10.2019, it would block all flights that can be booked between 23.10. - 27.10.2019 as well as 03.11. - 04.11.2019, but allows to book from 28.10. - 02.11.2019.

<Restriction>
    <DateRestrictions Invert="true">
        <DateRestriction MinBookingOffset="P5D" MaxBookingOffset="P10D"/>
		<DateRestriction Start="2019-11-05"/>
    </DateRestrictions>
</Restriction>

StayRestriction element﻿

A StayRestriction element may have the following attributes:

  • Min: Period (for example, P1D, P5D). The minimum length of stay.

  • Max: Period. The maximum length of stay.

  • Mode: Possible values:

    • Hotel: The lengths of stay specified in Min and Max only apply to the stay in the hotel.

    • Flight: The lengths of stay also take into account the (overnight) flight.

    • GroundTime: Only in the PXB2Tool; not supported in the Converter. See also GroundTime value in "Filters in the PXB2Tool".

Examples﻿

One restriction﻿

The following Restriction element discards all flights for a length of stay in the hotel of two days.

<Restriction>
    <StayRestrictions>
        <StayRestriction Min="P2D" Max="P2D" Mode="Hotel"/>
    </StayRestrictions>
</Restriction>

Two restrictions﻿

The following Restriction element discards all flights for a hotel-based length of stay of either two days or a hotel base length of stay between 5 and 6 days.

<Restriction>
    <StayRestrictions>
        <StayRestriction Min="P2D" Max="P2D" Mode="Hotel"/>
        <StayRestriction Min="P5D" Max="P6D" Mode="Hotel"/>
    </StayRestrictions>
</Restriction>

Restriction with Invert attribute﻿

The next sample will discard all flights except those ones that have a hotel-based length of stay of two days.

<SalesControlRoot>
    <Restrictions>
        <Restriction SortIndex="5">
            <StayRestrictions Invert="true">
                <StayRestriction Min="P2D" Max="P2D" Mode="Hotel"/>
            </StayRestrictions>
        </Restriction>
    </Restrictions>
</SalesControlRoot>

SourceRestriction element﻿

A SourceRestriction element may only have the Code attribute.

  • Code: The flight provider's code.

Examples﻿

One restriction﻿

The following restriction discards all flights from the flight provider with the code EK.

<Restriction>
    <SourceRestrictions>
        <SourceRestriction Code="EK"/>
    </SourceRestrictions>
</Restriction>

Restriction with Invert attribute﻿

The following restriction discards all flights except those from source EK.

<Restriction SortIndex="5">
    <SourceRestrictions Invert="true">
        <SourceRestriction Code="EK"/>
    </SourceRestrictions>
</Restriction>

TransportRestriction element﻿

note

Up until Sales control EDF version 2.2.3, the TransportRestriction element was named FlightRestriction. The usage of FlightRestriction is deprecated; it is recommended to use TransportRestriction instead. FlightRestriction remains as an alias for backwards compatibility.

A TransportRestriction element may have the following attributes:

  • Type: Possible values: Inbound and Outbound.

  • DepartureAirport: IATA code of the departure airport (for example DUS or PMI). The PXB2Tool supports a special notation in this attribute. See also Special notation for identical airports in "Filters in the PXB2Tool".

  • ArrivalAirport: IATA code of the arrival airport. The PXB2Tool supports a special notation in this attribute. See also Special notation for identical airports in "Filters in the PXB2Tool".

  • MinSegments: Minimum number of flight segments.

  • FlightNumber: (for example DE5514 or EK58). The PXB2Tool supports a special notation in this attribute. See also Special notation for identical airlines, booking classes and flight numbers in "Filters in the PXB2Tool".

  • BookingClass: (for example Y). The PXB2Tool supports a special notation in this attribute. See also Special notation for identical airlines, booking classes and flight numbers in "Filters in the PXB2Tool".

  • DepartureTimeMin: Time (Both hh:mm and hh:mm:ss are accepted). Earliest departure time. The PXB2Tool only supports this attribute from version 2.10.0. Earlier versions do not support this attribute.

  • DepartureTimeMax: Time (Both hh:mm and hh:mm:ss are accepted). Latest departure time. The PXB2Tool only supports this attribute from version 2.10.0. Earlier versions do not support this attribute.

  • ArrivalTimeMin: Time (Both hh:mm and hh:mm:ss are accepted). Earliest arrival time. The PXB2Tool only supports this attribute from version 2.10.0. Earlier versions do not support this attribute.

  • ArrivalTimeMax :Time (Both hh:mm and hh:mm:ss are accepted). Latest arrival time. The PXB2Tool only supports this attribute from version 2.10.0. Earlier versions do not support this attribute.

  • Airline: IATA airline code. The PXB2Tool supports a special notation in this attribute. See also Special notation for identical airlines, booking classes and flight numbers in "Filters in the PXB2Tool".

  • MinConnectingTimeDuration: Since SalesControl XSD version 2.1.2

    • This attribute enables the blacklisting via-flights according to their connecting time between ArrivalTime of segment 1 and DepartureTime of segment 2.

    • The time must be defined in minutes and is considered per stop - i.e. the maximum connecting time of all segments is evaluated for removing this flight.

    • This attribute is only supported in the PXB merge process from the Player version 2.37.0

Examples﻿

One restriction﻿

The following restriction discards

  • all inbound flights

  • from Düsseldorf (DUS)

  • to Dubai (DXB)

  • of the airline EK

  • with flight number EK58

  • which have two or more flight segments,

  • have booking class B

  • with a departure time between 20:40h

  • and 21:00h

  • and which arrive between 6:00h

  • and 07:00h in the morning.

<Restriction>
    <TransportRestrictions>
        <TransportRestriction Type="Inbound"
                           Airline="EK"
                           DepartureAirport="DUS"
                           ArrivalAirport="DXB"
                           MinSegments="2"
                           FlightNumber="EK58"
                           BookwhichingClass="B"
                           DepartureTimeMin="20:40"
                           DepartureTimeMax="21:00"
                           ArrivalTimeMin="06:00"
                           ArrivalTimeMax="07:00"/>
    </TransportRestrictions>
</Restriction>

Two restrictions﻿

The following restriction discards all flights that fulfill one of these conditions:

  • inbound flights with departure between 20:40h and 21:00h

  • flights that go from Düsseldorf (DUS) to Dubai (DXB)

Both restrictions are logically OR linked.

<Restriction>
    <TransportRestrictions>
        <TransportRestriction Type="Inbound"
                           DepartureTimeMin="20:40"
                           DepartureTimeMax="21:00"/>
        <TransportRestriction DepartureAirport="DUS"
                           ArrivalAirport="DXB"/>
    </TransportRestrictions>
</Restriction>

Restriction with Invert attribute﻿

In the next example, the Converter will convert only outbound flights from DUS to DXB with flight number EK58 or inbound flights with flight number EK55.

<Restriction SortIndex="5">
    <TransportRestrictions Invert="true">
        <TransportRestriction Type="Outbound"
                           DepartureAirport="DUS"
                           ArrivalAirport="DXB"
                           FlightNumber="EK58"/>
        <TransportRestriction Type="Inbound"
                           FlightNumber="EK55"/>
    </TransportRestrictions>
</Restriction>

HotelRestriction element﻿

note

The HotelRestriction element was added to the Sales control EDF with version 2.2.4.

A HotelRestriction element may have the following attributes:

  • Code: String. Used to restrict on the selling HotelCode.

  • GiataID: Integer. Used to restrict on the Giata ID of a product.

  • GoalID: Integer. Used to restrict on the GOAL ID of a product.

  • LocalSupplier: String. Used to restrict on the local supplier code that is used for the incoming data feed.

PriceRestriction element﻿

A PriceRestriction element may have the following attributes:

  • MinPrice: Integer. Flights with this price or a higher one are discarded.

  • Type: Possible values: Scheduled, Inbound and Outbound. Scheduled flights are those flights whose availability depends on the flight route. The PXB2Tool doesn't support the PriceRestriction element. See also Limitations in "Filters in the PXB2Tool".

Examples﻿

The following restriction discards all scheduled flights that cost more than 500.

<Restriction>
    <PriceRestrictions>
        <PriceRestriction MinPrice="500" Type="Scheduled"/>
    </PriceRestrictions>
</Restriction>

The following restriction discards all outbound flight with a price higher than 200.

<Restriction>
    <PriceRestrictions>
        <PriceRestriction MinPrice="200" Type="Outbound"/>
    </PriceRestrictions>
</Restriction>

Filters with mixed restrictions﻿

Different types of restrictions can be combined within one Restriction element. For instance, a DateRestrictions element and a PriceRestrictions element can be combined as shown in the examples below.

A one-way flight scenario combining a stay restriction with a price restriction doesn't make sense. In this scenario, the Converter ignores the stay restriction, i.e. the stay restriction is treated as if it was fulfilled. The PXB2Tool supports neither stay restrictions with one-way flights nor price restrictions.

Example﻿

The following restriction discards all outbound flights between July, 15th and July, 16th 2019 and which cost more than 150. Keep in mind that both restrictions must be fulfilled for the filter to take effect, i.e. a flight that fulfills the DateRestriction but not the PriceRestriction will still be processed.

<Restriction>
    <DateRestrictions>
        <DateRestriction Start="2019-07-15" End="2019-07-16"/>
    </DateRestrictions>
    <PriceRestrictions>
        <PriceRestriction MinPrice="150" Type="Outbound"/>
    </PriceRestrictions>
</Restriction>
