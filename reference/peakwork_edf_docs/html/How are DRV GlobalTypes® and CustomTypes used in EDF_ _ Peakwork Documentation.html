How are DRV GlobalTypes® and CustomTypes used in EDF?﻿

Last modified: 25 February 2026

For most of the EDF (e.g. hotel, flight, global extra EDF), the schema defines following structure for GlobalTypes and CustomTypes:

DRVGlobalType
	GTAttribute
		GT <!-- GT stands for GlobalType, is required! -->
		ST <!-- GT stands for SubType, is optional -->
		AT <!-- GT stands for AdditionalType, is optional -->
		CT <!-- GT stands for CustomType, is optional -->

DRV GlobalTypes® in the hotel EDF﻿

There are several locations in the EDF where DRV GlobalTypes® and CustomTypes can be defined:

  • regarding hotel attributes, see also DRVGlobalTypes and DRVGlobalTypes

    //HotelRoot/BasicData/DRVGlobalTypes
//HotelRoot/SellingData/DRVGlobalTypes

  • regarding extras, see also Extras

    //HotelRoot/SellingData/Extras
//HotelRoot/SellingData/Rooms/Room/Extras/
//HotelRoot/SellingData/Rooms/Room/ChargeBlocks/ChargeBlock/Extras

  • regarding cancellation policies, see also Non-refundable rates

    //HotelRoot/SellingData/Rooms/Room/DRVGlobalTypes@CT

DRV GlobalTypes® only﻿

To illustrate the use of DRV GlobalTypes® and CustomTypes in the EDF, the possibilities based on the fictional tour operator "UK Holidays" (UKH) will be displayed.

A GlobalType (GT) can stand alone or can be further specified by an optional SubType (ST) and / or AdditionalType (AT). In this example, the GlobalType is complemented by a SubType and an AdditionalType to describe it in more detail.

Example﻿

<GTAttribute GT="GT03-MASS" ST="ST03-CHMA" AT="AT03-EXCO" />

GlobalType

GT03-MASS

massage

SubType

ST03-CHMA

chocolate massage

AdditionalType

AT03-EXCO

extra cost

Using multiple SubTypes﻿

When using SubTypes, each <GTAttribute> element represents a single combination of GlobalType and SubType. To use multiple SubTypes (even if they are paired with the same GlobalType), multiple <GTAttribute> elements need to be defined.

Example:

<GTAttribute GT="GT03-MASS" ST="ST03-CHMA" />
<GTAttribute GT="GT03-MASS" ST="ST03-FBMA" />

In the example above, both the subtypes "ST03-CHMA" and "ST03-FBMA" are defined in separate <GTAttribute> elements, although they complement the same GlobalType "GT03-MASS".

CustomTypes only﻿

When a CustomType (CT) stands alone, a category must be stated. The categories refer to the defined categories of DRV GlobalType. Then the CustomType is defined.

Example 1﻿

<GTAttribute GT="GT03" CT="UKH-STOU2" />

Category

GT03

(accommodation attributes)

CustomType

UKH-STOU2

UKH Super Tour Nr.2

Example 2﻿

<GTAttribute GT="GT03" CT="CT03-STOU1" />

Category

GT03

(accommodation attributes)

CustomType

CT03-STOU1

UKH Super Tour Nr.1

Since Hub version 2.6.5 in web service requests all custom types which are not preceded by a DRV GlobalType® must at least be preceded by a stand-alone prefix, i.e. GT03\#UKH-STOU2 or GT03\#CT03-STOU1 in case of the above example.

DRV GlobalTypes® and CustomType combined﻿

A separate indication of the category is not required here because the GlobalType is defined. The CustomType is encoded according to rules described above. It is also possible to combine SubTypes and AdditionalTypes when using a CustomType, but only when a GlobalType is set.

Example 1﻿

<GTAttribute GT="GT03-CHPO" CT="UKH-KPOO" />

GlobalType

GT03-CHPO

Kids Pool

CustomType

UKH-KPOO

UKH Kids Club Pool

Example 2﻿

<GTAttribute GT="GT03-CHPO" CT="CT03-KPOO" />

GlobalType

GT03-CHPO

Kids Pool

CustomType

CT03-KPOO

Kids Club Pool

Example non-refundable rates﻿

The non-refundable-rates are defined as CustomTypes and have a specific structure starting with "FCP", e.g. "FCP-P8D":

<GTAttribute GT="GT05" CT="FCP-P8D" Start="2021-09-01" End="2021-10-31"/>
