CompatibleWith element﻿

Last modified: 25 February 2026

XPath: Extras/Extra/CompatibleExtras/CompatibleWith

The CompatibleWith element specifies the compatibility of the Extra element with other Extra elements. It has the attributes GroupId and Invert.

Extras with the CombiGroupId specified in GroupId are either compatible with the current Extra (Invert="false") or incompatible with it (Invert="true"). If Invert is set to "true", all elements with CombiGroupIds except for the ones specified in GroupId are compatible with the current Extra. Read also about the usage of Extra together with CompatibleExtras/CompatibleWith in the Example compatible extras.

If there are multiple CompatibleWith elements, it depends on the Invert attribute of the CompatibleExtras element how these CompatibleWith elements are joined logically:

  • When Invert="false" (i.e. the default), multiple CompatibleWith elements are joined by a logical OR.

  • When Invert="true", multiple CompatibleWith elements are joined by a logical AND.

GroupId attribute﻿

XPath: Extras/Extra/CompatibleExtras/CompatibleWith/@GroupId

The GroupId attribute refers to the CombiGroupId attribute of the Extra element.

Invert attribute﻿

XPath: Extras/Extra/CompatibleExtras/CompatibleWith/@Invert

The Invert attribute specifies whether an extra is compatible with another extra. The details depend on the Invert attribute of CompatibleExtras.

Possible values are true and false. The default value is false.

When CompatibleExtras has Invert="false"﻿

The Invert attribute specifies whether an extra is compatible or incompatible with the group that is specified in the GroupId attribute.

Values:

  • true: The Extra element is not compatible with the group that is specified in the GroupId attribute.

  • false: The Extra element is compatible with the group that is specified in the GroupId attribute.

In the example below, the current extra is compatible with all extras that do not have CombiGroupId="0".

<CompatibleExtras>
    <CompatibleWith GroupId="0" Invert="true" />
</CompatibleExtras>

When CompatibleExtras has Invert="true"﻿

The Invert attribute specifies whether an extra is compatible with the group that is specified in the GroupId attribute.

Values:

  • true: The Extra element is compatible with the group that is specified in the GroupId attribute.

  • false: The Extra element is not compatible with the group that is specified in the GroupId attribute.

In the following two examples, the current extra is compatible with all extras that have CombiGroupId="0".

Example 1:

<CompatibleExtras Invert="true">
    <CompatibleWith GroupId="0" Invert="true" />
</CompatibleExtras>

Example 2:

<CompatibleExtras>
    <CompatibleWith GroupId="0"/>
</CompatibleExtras>

The difference between these two examples is that they use different compatibility checks. See Invert attribute.

Special case﻿

When CompatibleExtras has Invert="true" and all CompatibleWith elements have Invert="false", the list of extras for this journey must contain at least one extra that does not have the group IDs mentioned in the CompatibleWith elements.

Example: There are two extras, namely extra 1 with the highest priority and extra 2 with a lower priority.

Extra 1:

<Extra CombiGroupId="1" SortIndex="1">
[...]
</Extra>

Extra 2:

<Extra SortIndex="2">
    <CompatibleExtras Invert="true">
        <CompatibleWith GroupId="1"/>
        <CompatibleWith GroupId="2"/>
        <CompatibleWith GroupId="3"/>
    </CompatibleExtras>
</Extra>

Extra 1 is added to the list of extras of this journey. Extra 2 can be added to the list because it has at least one CompatibleWith element without GroupId="1".

See also CompatibleExtras Invert="true" and CompatibleWith Invert="false".

Example compatible extras﻿

The CombiGroupId attribute of the Extra element and the CompatibleExtras element controls whether different groups of extras are compatible with one another.

Extras that have neither CombiGroupId nor GroupId of the CompatibleWith element are compatible with almost all other extras. The only exceptions are extras that exclude extras with CombiGroupId="0" explicitly. This is due to the default value of the CombiGroupId attribute, which is 0.

A typical extra without these attributes is the extra "handling fee", as detailed below:

<Extra>
    <Descriptions Visible="false">
        <Description>handling fee</Description>
    </Descriptions>
    <Charges>
        <Charge Amount="8" Calculation="PS">
            <Appliances>
                <Appliance Type="Person" MinAge="12" />
                <Appliance Type="Charge" Code="None" />
            </Appliances>
        </Charge>
    </Charges>
</Extra>

Compatibility should not be mistaken for applicability. The element Appliance specifies the price component or person the extra is applied to. An example would be an extra "Gala dinner" for which an early bird discount is applicable. Applying one extra to another only is possible if both extras are compatible with each other. Either they have the same CombiGroupId or a GroupId of the second extra is identical to the CombiGroupId of the first one.

Example incompatible extras﻿

Some extras are valid within the same time range but are not compatible with one another. This can be controlled with the help of the GroupId attribute and the CompatibleWith element. An example is given below.

In this example, the first extra has CombiGroupId="1" (in the Extra element). The second extra has GroupId="1" and Invert="true" (in the CompatibleWith element). This means that the second extra is incompatible with all extras that have CombiGroupId="1".

<Extra ApplianceCode="SO" CombiGroupId="1" SortIndex="0">
    <Restrictions>
        <Restriction>
            <DateRestrictions>
                <DateRestriction ApplyTo="Arrival" ApplyToMode="Hotel" Start="2016-09-11" End="2016-09-25" BookingStart="2015-09-30" BookingEnd="2016-11-07" ExtraMaxApply="99" />
            </DateRestrictions>
            <StayRestrictions>
                <StayRestriction Min="7" Max="21" />
            </StayRestrictions>
        </Restriction>
    </Restrictions>
    <Descriptions>
        <Description>reduction: 7 nights for the price of 6</Description>
    </Descriptions>
    <Reductions>
        <Reduction Percent="100" Mode="Last" Nights="7" DiscountedNights="1" Calculation="PS" />
    </Reductions>
</Extra>
<Extra ApplianceCode="FB1" CombiGroupId="2" SortIndex="1">
    <Restrictions>
        <Restriction>
            <DateRestrictions>
                <DateRestriction ApplyTo="Within" Start="2016-05-07" End="2016-11-06" BookingStart="2015-10-01" BookingEnd="2016-11-06" MinBookingOffset="P60D" />
            </DateRestrictions>
        </Restriction>
    </Restrictions>
    <CompatibleExtras>
        <CompatibleWith GroupId="1" Invert="true" />
    </CompatibleExtras>
    <Descriptions>
        <Description>early bird discount</Description>
    </Descriptions>
    <Reductions>
        <Reduction Percent="25.00" Calculation="PN" />
    </Reductions>
</Extra>

Example interaction of CompatibleExtras and CompatibleWith﻿

In this example, there are three extras:

  • extra 1 with CombiGroupId="1"

  • extra 2 with CombiGroupId="2"

  • extra 3 with CombiGroupId="3"

We want to decide whether extra 3 is valid. For this, we assume three different cases:

  • first case: both extra 1 and extra 2 are already in the internal list of valid extras

  • second case: only extra 1 is already in the internal list of valid extras

  • third case: only extra 2 is already in the internal list of valid extras

In the following four examples, the XML fragments describe extra 3.

CompatibleExtras Invert="false" and CompatibleWith Invert="false"﻿

<CompatibleExtras>
    <CompatibleWith GroupId="2"/>
</CompatibleExtras>

In this example, extra 3 is only compatible with extra 2. In other words, extra 3 is only valid if the internal list of valid extras contains extra 2 and nothing else.

  • In the first case, the list contains the extras 1 and 2. Extra 3 cannot be added to the list because it is incompatible with extra 1.

  • In the second case, the list contains only extra 1. Extra 3 cannot be added to the list because it is incompatible with extra 1.

  • In the third case, the list contains only extra 2. Extra 3 can be added to the list because it is compatible with extra 2.

CompatibleExtras Invert="false" and CompatibleWith Invert="true"﻿

<CompatibleExtras>
    <CompatibleWith GroupId="2" Invert="true"/>
</CompatibleExtras>

In this example, extra 3 is not compatible with extra 2. In other words, extra 3 is not valid if the internal list of valid extras already contains extra 2.

  • In the first case, the list contains the extras 1 and 2. Extra 3 cannot be added to the list because it is incompatible with extra 2.

  • In the second case, the list contains only extra 1. Extra 3 can be added to the list because it is compatible with extra 1.

  • In the third case, the list contains only extra 2. Extra 3 cannot be added to the list because it is incompatible with extra 2.

CompatibleExtras Invert="true" and CompatibleWith Invert="true"﻿

<CompatibleExtras Invert="true">
    <CompatibleWith GroupId="2" Invert="true"/>
</CompatibleExtras>

In this example, extra 2 must be in the internal list of valid extras. It doesn't matter if any other extras are also in the list.

  • In the first case, the list contains the extras 1 and 2. Extra 3 can be added to the list because the list contains already extra 2.

  • In the second case, the list contains only extra 1. Extra 3 cannot be added to the list because the list doesn't contain extra 2.

  • In the third case, the list contains only extra 2. Extra 3 can be added to the list because the list contains already extra 2.

CompatibleExtras Invert="true" and CompatibleWith Invert="false"﻿

<CompatibleExtras Invert="true">
    <CompatibleWith GroupId="2"/>
</CompatibleExtras>

In this example, extra 3 can be added to the list when at least one extra except extra 2 is in the list.

  • In the first case, the list contains the extras 1 and 2. Extra 3 can be added to the list because there is one extra in the list that is not extra 2.

  • In the second case, the list contains only extra 1. Extra 3 can be added to the list because there is one extra in the list that is not extra 2.

  • In the third case, the list contains only extra 2. Extra 3 cannot be added to the list because the list contains no other extra than extra 2.

  • If the internal list of valid extras is empty, the extra 3 cannot be added.

See also Special case.
