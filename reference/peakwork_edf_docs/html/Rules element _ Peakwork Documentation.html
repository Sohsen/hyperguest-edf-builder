Rules element﻿

Last modified: 25 February 2026

A rule in the calculation EDF gives information on how a calculation should be applied.

Rules are represented as different Rule elements within the container element Rules. Only if the restrictions in a Rule element are met by a given offer, the respective calculation will be applied.

Rules can be sorted according to their priority. The rules with the highest priorities are applied first (if the restrictions are met).

Per dynamic product component (hotel price, flight price, total), only one "starting" Rule can be valid at a time. One after the other, they are processed according to a certain sort sequence (SortIndex attribute in the Rule element).

After applying this first rule, other rules might be considered but they have to be compatible with this one valid rule (defined via the CompatibleWith/CompatibleWith element(s)). This way, a chain of rules can be applied to one component.

Please note that there only can be a maximum of 64 unique total CombiGroupIds defined in either <Rule CombiGroupId="X"> or in its references by <ComptibleWith GroupIds="X">. For more details, see Limitations.

Attributes﻿

  • Name: Specifies the name of the rule.

  • Operator: Possible value: and. Multiple restrictions are connected by a logical "and" within one rule.

  • SortIndex: Specifies the rule's priority among other rules.

    The lower the value, the higher the priority. Rules with a higher priority are checked for fitting restrictions first.

  • CalculationName: Specifies the calculation name indicated under "Rule Details" ("Identifier" field) in the tour operator system.

    The calculation name is the key to the actual calculation in the Calculations element. It references the calculation the rule belongs to.

  • CalculationCode: If the rule is available in an abbreviated or code form in the tour operator system, this will be indicated here. When using codes, the calculation relevant for the rule is not only referenced by the CalculationName but also by the CalculationCode.

    This attribute is optional.

  • CombiGroupId: Specifies the compatibility of different rules. This way, rules applicable to the same product component can be specified. For an example for the use of the CombiGroupId, see Rules and CombiGroupIds.

  • Mandatory: Possible values: true, false, disabled, include, exclude.

    • true: This is the default value. Therefore, setting Mandatory="true" doesn't do anything special.

    • false, disabled: This disables the rule. Not implemented in the Calc Plugin.

    • include: The Calc Plugin (since version 2.6.6) returns the price change in the MandatorySum attribute of the Response element and applies the rule to the price.

    • exclude: The Calc Plugin (since version 2.6.6) returns the price change in the MandatorySum attribute of the Response element but it doesn't apply the rule to the price.

      In both cases (include and exclude), the Player returns the price change when responding to a detail query.

      Please note: If the hotel EDF file contains extras with the Mandatory attribute set to Include or Exclude, this may lead to problems.

Elements﻿

  • Appliances: If the Appliances are used, the price ranges in the rules and calculations are considered per person. Therefore, you can use this appliance, if you want the flight, hotel and total net prices to be considered for each person. If the Appliances are used, the value Basis="Total" does not make sense and will be ignored. The attributes MinAge and MaxAge within an Appliance element specify whether a rule shall only be used for children or adults.

  • CompatibleRules: Helps to define which rules are compatible. If not set, only rules with the same CombiGroupId are compatible.

Restrictions﻿

For a description of the internal structure of the following restriction elements, please take a look at the XSD. Be aware that not all attributes and elements within the different restrictions are implemented. In case of uncertainty, please talk to your project manager.

  • HotelCurrencyRestriction: Since Box version 1.113.0. A rule/calculation can be restricted by the source currency that the supplier delivered within the cache-offer or for live offers within the currency that is used within the request towards the live supplier API.

    The HotelCurrencyRestriction may contain one or more Currency that contains the three-digit currency code according to ISO 4217.

  • LocationRestrictions: Restrictions on departure and arrival location. This element can applied for a wider range of location types - here, a location may be an airport, train station, etc. In this context, enums (e.g. ApplyToMode, StayMode, etc.) have been extended by the value Transport.

  • AirportRestrictions: Restrictions on departure and arrival airports; the airports may have the attribute MainSegmentAirports, for detailed information see Example for MainSegments.

  • DateRestrictions: Restrictions on travel and booking periods

  • WeekdayRestrictions: Restrictions on weekdays

  • BoardRestrictions: Restrictions on board codes

  • StayRestrictions: Restrictions on travel durations. Note that the Sequence attribute is not functional.

  • HotelRestrictions: Restrictions on hotels or hotel sources

  • GuestRestrictions: Restrictions on passengers, age or occupancy

  • FlightRestrictions: Restrictions on flights or flight source; only the outbound flight is considered for applying the rules

  • PriceRestrictions: Restrictions on total net prices

    • TransportRestrictions: Since Box version 1.73.0 Restrictions on specific transport connections (flights, railway):

      To calculate on tariff level you need the TransportRestriction element with the BookingClass attribute. To use different calculations based on price range you can use the range tag inside the calculations. Example:

      <?xml version="1.0"?>
<CalculationRoot xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance" xmlns:xsd="http://www.w3.org/2001/XMLSchema" SchemaVersion="1.011" xmlns="http://www.vilauma.de/edf/Calculation"
				   TourOperatorCode="2A" Currency="EUR" CreationDate="2018-12-11T10:00:05+00:00" >

		  <Rules>
			  <Rule Name="Rule_S" SortIndex="10" CalculationName="Rule_S">
				  <TransportRestrictions>
					  <TransportRestriction BookingClass="S" />
				  </TransportRestrictions>
			  </Rule>

			  <Rule Name="Rule_F" SortIndex="15" CalculationName="Rule_F">
				  <TransportRestrictions>
					  <TransportRestriction BookingClass="F" />
				  </TransportRestrictions>
			  </Rule>

		  </Rules>

		  <Calculations>
			  <Rounding Mode="Up">
				  <Appliances>
					  <Appliance Code="Transport" />
				  </Appliances>
			  </Rounding>
			  <Calculation Name="Rule_F" Mode="RelativeAbsolute" ApplyTo="TransportPrice">
				  <Charges>
					  <Charge Basis="PerPerson">
						  <Range Max="245" />
						  <Pricing Percent="25" Amount="60" />
					  </Charge>
					  <Charge Basis="PerPerson">
						  <Range Min="245" />
						  <Pricing Percent="25" Amount="70" />
					  </Charge>
				  </Charges>
			  </Calculation>
			  <Calculation Name="Rule_S" Mode="RelativeAbsolute" ApplyTo="TransportPrice">
				  <Charges>
					  <Charge Basis="PerPerson">
						  <Range Max="120" />
						  <Pricing Percent="15" Amount="30" />
					  </Charge>
					  <Charge Basis="PerPerson">
						  <Range Min="120" />
						  <Pricing Percent="15" Amount="50" />
					  </Charge>
				  </Charges>
			  </Calculation>
		  </Calculations>
</CalculationRoot>

Rules and distribution channels﻿

Additionally, distribution channels may play an important role. A distribution channel is represented by a Distribution element with a Channel element, which has a Name attribute. This Distribution/Channel/@Name construction may occur in a Rule element and in a hotel offer. Two distribution channels are identical if their Name attributes have the same value.

A rule will be applied to an offer in the following cases:

  • if the distribution channel of the rule is identical to the distribution channel of the offer

  • if the hotel offer has no distribution channel but the calculation has one

If the hotel offer has a distribution channel, this offer is only returned if the request has the same distribution channel.

Rules and restrictions﻿

A Rule element can be defined with different conditions (Restrictions). These restrictions specify whether the rule will be applied or not.

The first rule that fits according to the conditions (Restrictions) is then used on the product component (the calculations referred to in the Rule element will be applied to the respective price) while all the others are ignored. Then, further rules are searched and processed for the remaining product components. They have to be compatible with the rule(s) already applied.

Main structure

<Rules>
    <Rule Name="" Operator="" SortIndex=""
            CalculationName="" CalculationCode=""
            CombiGroupId="" Mandatory="">
        <AirportRestrictions />
        <DateRestrictions />
        <WeekdayRestrictions />
        <BoardRestrctions />
        <StayRestrictions />
        <HotelRestrictions />
        <GuestRestrictions />
        <FlightRestrictions />
        <PriceRestrictions />
        <Appliances />
        <CompatibleRules />
    </Rule>
</Rules>

Combination of restrictions

In the following example, for products with the following specifications, the calculation with the name "BKK1" is valid:

  • destination airport "BKK" AND

  • arrival between 01/11/2012 and 30/11/2012 AND

  • a flight from flight source "XYZ"

<Rule Name="BKK flight source XYZ" SortIndex="1" CalculationName="BKK1" CombiGroupId="2">
    <AirportRestrictions>
        <ArrivalAirports>
            <ArrivalAirport IataCode="BKK" />
        </ArrivalAirports>
    </AirportRestrictions>
    <DateRestrictions>
        <DateRestriction Start="2012-11-01" End="2012-11-30" ApplyTo="Arrival" />
    </DateRestrictions>
    <FlightRestrictions>
        <FlightRestriction>
            <Sources>
                <Source ID="XYZ" />
            </Sources>
        </FlightRestriction>
    </FlightRestrictions>
</Rule>

Rules and CombiGroupIds﻿

For each product (hotel, flight, total) one rule will be chosen as a valid one in a first step. For the selection process, the rules are sorted according to their SortIndex attributes. Rules with a small index will be considered first. After applying a first rule, other compatible rules might be chosen as valid, too.

Example:

The calculation has (amongst others) three rules for the calculation of the flight price. The actual offer under consideration fits the restrictions for all these rules.

In this case, the rule with the smallest value in SortIndex, SortIndex="1", is going to be chosen. The CombiGroupId of the rule is saved.

After applying the calculation referred to in the first rule (with Name="BKK flightsource XYZ"), a second rule will be taken into consideration, that has to be compatible with the CombiGroupId of the first rule: the one with Name="BKK flightsource XYZ_3" and CombiGroupId="4". If the restriction in this rule fit (for possible PriceRestrictions the newly calculated price has to be taken into consideration), the respective calculation will also be applied. This way, you can specify chains of rules and calculations that can applied to one product.

<Rules>
   <Rule Name="BKK flightsource XYZ" Operator="and" SortIndex="1" CalculationName="BKK5"
         CombiGroupId="2">
      <AirportRestrictions>
      ...
      </PriceRestrictions>
      <Appliances />
      <CompatibleRules>
          <CompatibleWith GroupId="4"/>
      </CompatibleRules>
   </Rule>
   <Rule Name="BKK flightsource XYZ_2" Operator="and" SortIndex="5" CalculationName="BKK7"
         CombiGroupId="1">
      <AirportRestrictions>
      ...
      </PriceRestrictions>
      <Appliances />
      <CompatibleRules/>
          <CompatibleWith GroupId="2"/>
      </CompatibleRules>
   </Rule>
   <Rule Name="BKK flightsource XYZ_3" Operator="and" SortIndex="3" CalculationName="BKK6"
         CombiGroupId="4">
      <AirportRestrictions>
      ...
      </PriceRestrictions>
      <Appliances />
      <CompatibleRules/>
          <CompatibleWith GroupId="2"/>
      </CompatibleRules>
   </Rule>
...
</Rules>

Example BookingClass and CabinClass attributes﻿

Both the attributes CabinClass and BookingClass can be used in the FlightRestrictions/FlightRestriction element to define calculation rules based on the:

  • cabin class, i.e. "economy", "comfort", "first", "business"; the same for every tour operator. Within the flight EDF, the cabin class is defined as the Class attribute with the values "Economy", "Comfort", "First", "Business", "Premium".

  • booking class, e.g. "Y", "C", etc.; defines the tariffs for the seats in the cabin; used together with the CabinClass attribute and might be tour-operator-specific. The BookingClass attribute is available in the calculation EDF since Box version 1.70.0. Within the flight EDF, it is required for TOMA bookings.

<Rule CabinClass="Economy" BookingClass="Y"></Rule>

Example for main segments﻿

There are two different offers with a flight route from DUS to NYC with two segments:

  1. The first segment is DUS to FRA and the second segment is FRA to NYC; the second segment is flagged as the main segment.

  2. The first segment is from DUS to LAS and the second segment is from LAS to NYC; the first segment is flagged as the main segment.

The following rule is applied:

<AirportRestrictions>
   <DepartureAirports MainSegmentAirports="true">
    <DepartureAirport IataCode="DUS"/>
    <DepartureAirport IataCode="FRA"/>
   </DepartureAirports>
   <ArrivalAirports MainSegmentAirports="true">
    <ArrivalAirport IataCode="NYC"/>
   </ArrivalAirports>
</AirportRestrictions>

With this rule the first offer would match because the main segment is FRA to NYC. The second offer would not match because the main segment is DUS to LAS.

You can also set the attributes to different values in DepartureAirports and ArrivalAirports; the following rule is applied:

<AirportRestrictions>
   <DepartureAirports MainSegmentAirports="true">
    <DepartureAirport IataCode="DUS"/>
    <DepartureAirport IataCode="FRA"/>
   </DepartureAirports>
   <ArrivalAirports>
    <ArrivalAirport IataCode="NYC"/>
   </ArrivalAirports>
</AirportRestrictions>

In this example the rule matches both offers because the main segment has DUS or FRA as a departure airport. This rule ignores the arrival airport.

Important:

It is not possible to use the AirportRestrictions element for both the main segment and the whole flight route. You can check only one restriction; i.e. it is not possible to check if your flight route is from DUS to NYC and there is a main segment from FRA to NYC.

Example calculation rule on country﻿

There are two ways to restrict a calculation on the country:

  • by using the LocacationRestrictions element - note that it applies only on the location of the outbound.

  • by using the HotelRestrictions/HotelRestriction/Location element.
    Code example:

    <Rule Name="name" SortIndex="1" CalculationName="name" CombiGroupId="1">
	<HotelRestrictions>
		<HotelRestriction>
			<Locations>
				<Location Type="Country" Code="US"/>
			</Locations>
			<Sources>
				<Source ID="source"/>
			</Sources>
		</HotelRestriction>
	</HotelRestrictions>
	<CompatibleRules>
		<CompatibleWith GroupId="1" Invert="false"/>
	</CompatibleRules>
</Rule>
