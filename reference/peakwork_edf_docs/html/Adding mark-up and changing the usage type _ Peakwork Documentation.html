Adding mark-up and changing the usage type﻿

Last modified: 25 February 2026

Mark-up﻿

You can add additional a mark-up as an extra in the emerging EDF data. The resulting extra will be applied to the total price of the offer. It will be written into EDF in the SellingData element.

These mark-ups can be on a percentage basis or an absolute one. If such a mark-up shall be applied, Peakwork need to be informed about the value to apply and whether the mark-up is absolute or shall be a percentage extra.

The two examples below illustrate how the Extra element in the resulting EDF file will look like in both cases.

On a percentage basis﻿

Enrichment information needed: markup.percentage=20

Resulting Extra element in EDF:

<Extra GlobalType="IC" ApplianceCode="ZU">
    <Descriptions>
        <Description>Mark up - Percentage</Description>
    </Descriptions>
    <Charges>
        <Charge Percent="20.00" Calculation="PS">
            <Appliances>
                <Appliance Type="Extra"/>
                <Appliance Type="Charge" Code="None"/>
                <Appliance Type="Charge" Code="Board"/>
                <Appliance Type="Charge" Code="ExtraDay"/>
                <Appliance Type="Charge" Code="BaseCharge"/>
            </Appliances>
        </Charge>
    </Charges>
</Extra>

Absolute﻿

Enrichment information needed: markup.absolut=20

Resulting Extra element in EDF:

<Extra GlobalType="IC" ApplianceCode="ZU">
    <Descriptions>
        <Description>Mark up - Absolute</Description>
    </Descriptions>
    <Charges>
        <Charge Amount="20.00" Calculation="PS">
            <Appliances>
                <Appliance Type="Extra"/>
                <Appliance Type="Charge" Code="None"/>
                <Appliance Type="Charge" Code="Board"/>
                <Appliance Type="Charge" Code="ExtraDay"/>
                <Appliance Type="Charge" Code="BaseCharge"/>
            </Appliances>
        </Charge>
    </Charges>
</Extra>

Change of usage type﻿

Hotel EDF files can either be used to produce hotel only or package data. To change an EDF file meant for hotel-only products into a file used for a package production, some information needed for the package combination price calculation is must be included in the resulting EDF.

If you like to change the usage type of the EDF, one of the following two specifications is needed.

If the EDF is produced for a package product, the ProgramType attribute from the BasicData element of the raw EDF will be deleted. The Usage attribute of the EDF will be changed from Hotel to Package. All Enrichment EDF files that shall be applied to this EDF therefore need to have Usage="Package", too.

FlightSeasonIdentifier﻿

Usually the SeasonIdentifier of hotel and flight EDF have to match to enable the production of a package product and the calculation of a price for the product. Some flight EDFs, however, do not have a SeasonIdentifier. If an identifier is included in the hotel EDF but not in the flight EDF the matching of identifiers cannot be used as a necessity for combining them.

The attribute FlightSeasonIdentifier specifies whether the season identifier of the flight EDF has to match the identifier of the hotel EDF (value Match) or if all flight EDF, independent of their identifier might be combined with the hotel EDF (value All).

When a hotel EDF shall be used to produce package products, the intended value for this attribute must be set.

Example﻿

Enrichment information needed: enrichment.package.flightSeasonIdentifier=All

Resulting attribute in EDF:

<SeasonDefinitions Identifier="w5"
    Start="2016-05-01" End="2016-10-31"
    FlightSeasonIdentifier="All"/>

HotelPriceTable﻿

The price table is used to connect flight and hotel when calculating package prices. in the flight EDF it can be specified which HotelPriceTable shall be used for the calculation of the prices. This price table in the hotel EDF does not only contain the price for the hotel but also contains prices for the flight. The package price will be calculated using prices from this table.

The HotelPriceTable used for package prices in the hotel EDF usually is called "FLUG". This value can be set using the enrichment process.

Example﻿

Enrichment information needed: enrichment.package.hotelPriceTable=FLUG

Resulting attribute in the BaseCharges element in EDF:

<BaseCharges HotelPriceTable="FLUG"
    SeasonStrategy="Hotel"
    SeasonStrategyMode="Stay" CalculationMode="P">
